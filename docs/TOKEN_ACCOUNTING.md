# Token 预留与缓存账本

## 2026-10-13 的故障

线上主题 5502 的一次实际调用为 **5,858 token**，却预留 **28,008**；同类调用大多实际约5,800、预留约28,000。主题14127的一条 ikarilink 点名被单帖预算拦住：已用97,669，上限120,000，旧算法要求27,904。这不是模型决定不理，也不是 DeepSeek 余额不足。

根因是把 UTF-8 字节数直接当作输入 token，再加最大输出；中文和 JSON 的预算被严重高估。全站额度用户已调到3,000,000，本次问题主要是单帖额度；不能靠一再加额度解决估算错误。

**状态：已通过最终273项PostgreSQL回归并切换修复；线上核验与备份证据见ACCEPTANCE。**

## 新计数与边界

- 官方 DeepSeek V4 路由使用随包离线分词器 JSON，计数结构化文本、工具参数，保留10%及聊天封装余量；图片按官方每张至多1,024 token预留。它仍是估算，实际账单以接口返回为准。
- 其他兼容路由仍用字节上界，界面明确标识。没有运行时下载，也不运行分词器压缩包中的示例或远程代码。
- 预算锁、日/单帖/任务额度和调用后结算保留；不把缓存命中冒充免费 token。管理员研究、全量个人贴导入不应占用后来普通互动的单帖额度，但继续占全站额度。
- 只判断表情时不检索无关用户记忆，背景限制为首帖及最近六条；新发言与背景不重复输入。需要正文时仍使用正常上下文。
- 服务商明确的调用前拒绝，如官方DeepSeek的401/429，释放未执行预留；超时、5xx和无用量的未知结果保守保留。历史未知失败不凭空退款。

## 缓存怎么查看

管理员打开 **运行记录 → 模型用量**。每次显示实际/预留、输入/输出、缓存命中/未命中和可用的思考计数；日汇总显示缓存统计覆盖了多少次调用。旧记录只有总数，缓存明细显示“未记录”，不会补造为0或伪造命中率。

DeepSeek自动缓存相同前缀，命中由接口的 `prompt_cache_hit_tokens` 或 `prompt_tokens_details.cached_tokens`报告。命中输入仍属于总token，但价格与未命中输入不同；本站token额度不是货币账单。缓存是尽力而为，不保证次次命中。

来源：[官方Token说明](https://api-docs.deepseek.com/quick_start/token_usage/)、[缓存](https://api-docs.deepseek.com/guides/kv_cache/)、[响应用量字段](https://api-docs.deepseek.com/api/create-chat-completion/)、[图片Token上限](https://api-docs.deepseek.com/guides/vision/)。分词器来源及SHA256见 `backend/suenmeow/assets/NOTICE.md`。
