# 共享人格与个人贴编排

所有登录用户在「人格与提示词」只读查看全部人格、全局草稿编排及其引用的工作模块。包括缺少旧 persona 标记的受保护角色文件：按受保护记录及管理员持有的旧角色文件名兼容识别，额外返回只读分类字段，不修改原始内容、版本或元数据。原有本人模块与明确授权模块仍可编辑；读取权限不会增加写权限、公开其他未引用的私有系统模块或暴露授权名单。

## 用户操作

到「个人贴编排」新建编排，选择自动发现的本人个人贴，或填写主题 ID；从全部人格中为五条路由分别添加、移除和排序。空列表表示这条路由不附加人格。保存入口固定右下角，显示未保存状态，支持快捷键和离开提醒。

每人最多10篇个人贴编排，每篇只能有一个编排，每条路由最多40个不同人格、合计内容不超过200,000 UTF-8字节。绑定需要已有论坛私信验证身份，核验稳定作者 ID、公开性、首帖与管理员配置的「個人帖」分类；不能指定他人主题、私信或受限主题。绑定主题不可直接改写，另一篇本人主题需新建草稿。

## 可选审核（默认关闭）

「人格与提示词」和「个人贴编排」展示同一个“人格与个人贴编排需要管理员审核”开关，只有管理员可修改，默认关闭。关闭时，本人个人贴编排保存并重新核验身份、分类和公开性后直接生效；用户也可主动启用已保存版本。开启后，保存为待审核草稿，管理员发布后生效；既有生效版本继续运行。

管理员始终能查看所有用户的编排、所有者、主题链接、草稿与生效版本，审核发布或停用。开关变化保留已生效版本，不批量启用待审核草稿；已停用编排不会被人格更新重新启用。开启审核时将现有人格作为可使用基线，此后修改单独等待审核。开关采用版本检查，冲突返回409。

## 人格发布与工作规则

用户仍只能创建自己的或编辑明确授权的人格，不能改动只读共享人格。审核关闭时，人格保存后直接可用，并更新已生效编排中对它的使用；开启时保留旧可使用内容，新内容须管理员“审核并发布人格”，或在审核该个人编排时一并发布选定人格。人格的草稿和可使用版本号分别展示。

人格发布只更新该人格。若全局已发布编排使用它，则创建只含人格变化的新快照，保留已发布系统工作规则、全局顺序和策略；不会顺带发布这些项目的草稿。把系统模块改标为人格也不能绕过全局发布。系统提示词和全局编排始终需要管理员发布。

个人编排固定顺序与生效人格内容；后续已批准的人格发布可刷新使用内容，产生新运行代次。未审核人格修改、个人草稿修改和删除不会改变旧生效内容。停用、编排重新生效或人格发布会使相关旧回复与Agent草稿失效；更新后仍复核每路200,000字节限制，超限整次修改回滚。

## 运行范围与安全

按论坛站点和既有主题 ID选择，仅绑定的本人公开个人贴可使用。最新发言者可以是访客，仍按首帖作者判断；用户在其他主题发言不会带走自己的编排。论坛连接、来源分类或账号身份变化时停止使用，管理员须重新核验发布。停用后恢复全局编排。

专属编排替换各路由的人格部分，然后保留该事件全局发布快照中的所有非人格工作模块，最后保留服务端安全规则。用户不能通过编排更改策略、模型、预算、鉴权、工具或发送授权。

普通回复的规划、正文、摘要与自动记忆使用此编排；目标明确的管理员 Agent 回复草稿及论坛事件自动研究也使用它。管理员纯研究聊天和私密任务保持原有隔离。个人贴全量记忆导入固定当时的专属记忆路由，版本变化后停止旧任务。发送前再次核验主题作者、公开性和运行代次，继续经过统一发送门；发布编排不会启用发送或追补积压。

新增 `topic_pipelines` 表和 `topic_pipeline_lock`，另有 `topic_pipeline_settings`、`persona_publications`，需显式 init。版本冲突返回409并保留网页未保存修改。个人编排保存本身不改变全局发布版本；显式发布在全局使用的人格会产生仅人格变化的快照和新水位，仍不改变运行模式或补发积压。实测证据见 [ACCEPTANCE.md](ACCEPTANCE.md)。
