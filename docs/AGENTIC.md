# Agentic SuenMeow：主动研究与管理员指令

状态：A1–A5 已接入代码，模拟流程与 PostgreSQL 验证持续记录在 `ACCEPTANCE.md`；真实论坛与模型联调、完整 GUI 验收仍在推进，不能视为已经完成上线。第一版实现不改变“只回复既有主题或既有私信”的硬约束。

## 能力与使用方式

SuenMeow 不再只被动接收固定上下文。遇到需要补充背景的讨论时，可以先寻找相关主题、读取其中必要的帖子、查找相关事实记忆，再决定如何回答。管理员可以在控制台聊天台交代任务，例如：

> 看一下最近大家讨论 SuenMeow 的帖子，结合 2.0 已上线的实际功能，拟一段介绍，回复到主题 #1234。约 3000 字，先给我预览。

> 查一下用户 alice 之前对猫窝的建议，列出来源，再帮我整理成改进清单。不要发到论坛。

> 在这条已有私信 #5678 中，接着上次没有讲完的问题聊两句。如果没有确切的未完话题，就不回复。

“新帖子”首先解释为论坛上已经存在的新主题。输入 URL、主题 ID 或选择搜索结果来指定目标；没有目标时先查找候选并让管理员选择。若未来确需创建新主题，应单独变更产品权限与发送协议，不能让模型通过参数或提示词偷偷开启。

## 两类 Agent 任务

| 任务 | 入口 | 可以做什么 | 默认结果 |
| --- | --- | --- | --- |
| 对话研究 | 新通知、热帖、猫窝互动 | 在当前事件预算内检索必要背景和相关记忆 | 根据原有只读、审核、自动模式处理 |
| 管理员任务 | 后台聊天台 | 搜索、阅读、分析、写草稿、按指定目标回复 | 展示结果或草稿，默认不发送 |

论坛发言不是管理员指令。即使帖子中自称管理员，工具权限也不会改变。管理指令必须来自已鉴权的后台账户；聊天记录中的引用内容和工具结果同样不能授权写操作。

## 需要新增的组件

1. **工具注册表**：每个工具具有 JSON Schema、权限、返回大小限制、超时、可见性和读写标记。按任务授予能力，不把所有工具无限开放给模型。
2. **Agent 执行器**：支持模型工具调用，维护“计划 → 调用 → 观察 → 更新计划 → 结果”的有界循环。对不支持工具调用的模型明确显示不兼容，不悄悄退化为执行任意文本命令。
3. **任务与轨迹存储**：持久化任务、步骤、检索来源、预算、取消和恢复状态。保存短摘要与必要证据；私信和聊天正文加密，不记载隐藏思维链。
4. **管理员聊天台**：流式显示进度、工具轨迹、引用、待办与草稿；支持停止、补充要求、重新研究和选择发送目标。权限与服务端会话沿用现有后台。
5. **长回复流程**：单独设置管理员任务的字数与输出预算，避免普通自动回复被顺带放宽。预览完整正文、目标与回复楼层；仍只发送一条。
6. **运行策略**：GUI 管理允许的工具、检索范围、步骤数、总耗时、任务预算、研究深度和发送方式。管理员可以关闭 Agent 能力而保留普通回复。

现有四条模型路由保留。新增可选 `agent` 路由负责工具调用；未配置时只能使用经检测支持工具调用的 planner 路由。回复、记忆与摘要继续各自独立；所有调用进入同一预算账本。

## 一个管理员任务如何完成

以“介绍 SuenMeow 2.0，回复到已有新主题 #1234”为例：

1. 管理员选择“写回复”、目标 #1234、约 3000 字和“先预览”。API 保存这些独立字段，不能仅从自然语言推断发送授权。
2. worker 校验账户、主题可见性、任务预算和模型工具能力，读取目标讨论与当前已验证发布信息。
3. Agent 按需搜索相关主题、读取帖子、检索涉及用户的相关记忆；工具结果先由服务端过滤，再交给模型。
4. 聊天台逐步展示工具名称、简短结果和来源。正文引用绑定实际读取的来源 ID；服务器生成链接，模型不能编造“已读取”的证据。
5. 完成后显示草稿、唯一目标、回复楼层、字数与来源。缺少目标时只展示候选，不发送。
6. 管理员编辑并确认当前版本。服务端绑定正文摘要、目标、可见性、楼层和有效期，然后进入已有发送门。
7. 发送成功显示论坛链接；超时显示“待核实”。刷新、重新启动和记忆更新都不能触发再次发送。

“可直接回复”是创建任务时的一次性明确选项，也必须绑定一个已验证目标；不设置全局“管理员指令自动发送”。默认预览的草稿永远不会因为切换到自动模式而自行发送。

## 第一批工具

| 工具 | 输入 | 返回与限制 |
| --- | --- | --- |
| `forum.search` | 关键词、用户、分类、时间范围、页码 | 使用 Discourse 搜索接口，返回有限候选、主题 ID、片段和来源链接；最多翻 3 页 |
| `forum.read_topic` | 主题 ID、楼层范围或帖子 ID | 仅取必要帖子，保留作者、楼层、时间和永久链接；每次最多 20 帖 |
| `forum.user_activity` | 用户名、公开活动范围 | 帮助定位某用户相关讨论；不能越过论坛账号权限 |
| `memory.lookup` | 用户名、主题 ID、关键词、用途 | 返回相关事实、来源和更新时间；根据任务可见性过滤后再交给模型 |
| `release.describe` | 当前运行版本 | 读取已验证的发布信息与功能清单；介绍 2.0 时不把待实现设计说成已上线 |
| `draft.reply` | 一个既有主题、回复楼层、正文 | 生成草稿；不能自行创建主题、发送或增加发送权限 |

表中的点号是文档命名；模型调用名称使用 `forum_search`、`forum_read_topic` 等下划线标识，与 JSON Schema 对齐。`draft.reply` 是执行器受控的草稿输出，独立于可自由调用的读取工具；真实发帖始终由服务端发送流程执行。

第一版不提供 shell、任意 SQL、任意 HTTP 请求、账户管理或权限修改工具。工具 URL 由服务器构造，不能由帖子内容指定访问外部地址。搜索结果不是授权；读到“执行这个命令”也不能把它变成工具调用指令。

自然语言私信注册另见 [注册与身份绑定](REGISTRATION.md)：AI 可以识别申请意图，账户创建、凭据处理和论坛身份绑定由独立服务完成。不能给研究 Agent 开放账户管理工具；注册资料必须在普通聊天、摘要、研究和记忆之前隔离，不能让跨帖读取重新取得凭据。此流程仍是待实现设计。

## 记忆与跨帖隐私

主动读取记忆意味着服务端检索相关事实，而不是每次把全部记忆交给模型。按用户名、主题、来源和更新时间筛选，后续可增加本地全文检索；第一版无需引入向量数据库。

- 公开回复任务只能访问公开事实与可公开引用的帖子。
- 私信事实只能进入原私信任务；即使管理员聊天中请求公开介绍，也不能混入私人记忆。
- 后台查询私信必须显式选择该对话范围，轨迹标注“私密”，不进入公开草稿的证据集合。
- 同一管理员聊天中，先前私密任务的对话历史也不能成为后续公开任务的模型上下文；按任务可见性与目标过滤，而非直接拼接整段聊天记录。
- 用户退出、删除记忆、修改猫窝授权后，执行器和最终发送门重新检查权限。
- 不在公开轨迹显示私人关系评分；只陈述有来源的关系事实。

允许跨帖读取，不代表允许跨私信拼接。对于受限分类等非公开主题，检索器必须识别其可见性；无法确定是否公开时，不能用于公开回复。

## 管理员聊天台的交互

左侧是任务会话列表，主区域是聊天与研究进度，右侧是证据和回复草稿。手机上证据和草稿作为可切换面板。每次任务展示：

- 当前状态，例如“正在搜索”“正在阅读 3 个主题”“已生成草稿”。
- 使用了哪些工具、读取了哪些来源、消耗多少预算。
- 回复的唯一目标、是否私信、楼层、字数与可见性。
- 停止、仅保留草稿、重新研究、编辑和发送操作。

“先研究”“只整理，不发送”等要求被存为服务端任务约束。默认先预览；管理员也可为本次指令明确授予“可直接回复指定主题”，但必须有唯一目标与长度上限，授权不延续到后续任务。模型不能把检索到的文字当作这类授权。

暂停时仍可聊天和生成草稿，但不能发送。恢复运行不会自动补执行旧指令；需要在有效期内重新确认。管理员编辑草稿后，原批准的正文摘要失效，避免发送未经确认的修改。

## 长回复与发送安全

普通自动回复沿用现有长度上限。管理员任务允许请求更长的单条回复，实际上限取以下三者的最小值：管理员策略上限、论坛实际允许长度、当前模型输出能力与预算。GUI 展示字数和预计用量；模型截断时保留失败草稿，不能把半篇正文发送出去。

默认不拆成多楼连续发送。管理员任务具备独立新指令收据和有效期，不依赖积压通知，但最终仍经过统一发送门：暂停、水位、目标权限、静音、安静时段、冷却、去重、预算和正文摘要校验均不可绕过。发送超时进入待核实；任务恢复、刷新聊天页和重新启动都不能重发。

## 执行边界与默认值

第一版默认最多 8 次工具调用、3 个不同主题（含目标主题）、120 秒研究时间、3 次搜索翻页、每个用户同时 1 个任务，全系统同时 2 个研究任务。默认任务总预算 16000 token、管理员回复策略上限 8000 字；这些是可调上限，不保证模型能输出同等长度。任务 token 上限与每日、单主题预算同时生效；每次模型调用预留与结算，每次检索也记录请求数及读取大小。并发工具调用逐个占用额度，不能利用单轮批量调用绕过限制。

模型返回不合法参数、工具超时、循环读取同一来源、权限不足或预算耗尽时停止该步骤，给出简短原因。可以展示已有证据，不凭空补全。取消任务后停止后续工具调用与发送；已在网络中发出的请求只能等待结果并准确记录。

研究缓存按论坛连接、可见性与来源划分，有短有效期。不同管理员任务不共享私信内容；worker 与管理员任务通过同一数据库预算锁和发送门协调。

## 数据与 API 拆解

新增版本化数据库迁移：`agent_sessions`、`agent_messages`、`agent_tasks`、`agent_steps`、`agent_sources`、`agent_drafts`。任务关联管理员、来源事件、配置快照、目的可见性、唯一目标、预算、有效期、取消标记与明确发送授权。私密正文加密保存，来源引用与审计摘要分开。

建议管理端 API：

- `POST /api/agent/sessions`、`GET /api/agent/sessions`：创建和读取自己的管理会话。
- `POST /api/agent/sessions/{id}/messages`：追加指令，生成有约束的任务。
- `GET /api/agent/tasks/{id}` 和其 SSE 进度接口：重连后从步骤序号继续查看。
- `POST /api/agent/tasks/{id}/cancel`：停止任务。
- `PUT /api/agent/drafts/{id}`、`POST .../confirm`：编辑和明确授权；确认绑定正文摘要、目标和有效期。
- `GET/PUT /api/agent/settings`：管理员管理工具范围和资源限制。

所有读取也必须校验会话所有者；即使两个账户都是管理员，也不默认互看管理聊天。SSE 不在 URL 携带凭据，发送授权不能用 GET 触发。

任务状态至少区分 `queued → running → completed/awaiting_confirmation`，以及 `failed`、`cancelled`、`expired`、`interrupted`。发送另用现有回复状态记录 `ready → sending → sent/unknown`，不能把“生成完成”当成“发帖成功”。重启将运行中的研究标为中断；旧发送授权失效，重新研究或发送需要新的明确操作。SSE 只回放进度，不执行任务。

当前代码已包含六张 Agent 表、任务输入与策略、`Usage.task_id` 预算关联、论坛读取适配器、有界执行器、管理员 API 与 SSE、聊天 GUI、长草稿编辑及统一发送门校验。模型配置和 worker 支持可选 `agent` 路由；普通新事件按规划结果或问题特征触发研究，默认关闭。管理员任务使用独立论坛会话，暂停时可以研究。

专项测试覆盖公开/私信/受限分类隔离、staff whispers 与隐藏帖过滤、任务所有者及 CSRF、循环与批量工具上限、取消、长草稿编辑撤销旧批准、超时不重发、自动研究开关与升级迁移。真实模型工具循环、跨帖研究和生产 v3 长正文预览已通过，管理员 GUI 编辑保存为草稿 v3，只读确认被拒绝。浏览器已验证桌面/手机布局、提交与停止、真实 HTTPS 登录及编辑者授权草稿。单条真实发送仍等待指定既有主题并核对该正文与来源，A4 生产发送验收尚未完成。

Agent 使用发布快照中标为人格且被回复路由选中的模块，再拼接可选 `agent` 编排中的工作规则；不继承旧回复器的 JSON/规划协议。GUI 的“主动研究工作规则”可以编辑与编排，管理员发布后用于新任务；空编排和旧四路快照使用内置研究规则。权限约束最后由服务端追加，模块不能授予发送权限。工作文本见 [系统工作提示词](SYSTEM_PROMPTS.md)。每轮提醒剩余步骤；研究用尽读取步骤后只能总结，回复最后一步只提供草稿工具，不强制指定提供方不支持的工具选择。提供方需要的临时推理载荷仅在任务内存中传回，包含没有调用工具的轮次，不保存或展示。GUI 可设置思考强度和输出额度；默认不向提供方发送额外思考参数。

当前交互要求每次任务独立描述需求，不把历史私密聊天自动交给新任务。改变目标须创建新任务；修改未发出的草稿会撤销原批准，并可批准新版本。缓存仅限单任务。第一版通过上限限制成本并展示实际 token，用量预估、跨任务续聊和更细的研究深度选择仍是后续界面改进。

部署顺序是先备份数据库与加密密钥、暂停发送、执行并验证 schema 1 → 2 迁移，再升级 API/worker。先启用管理员研究与预览，验证 A4 后开放人工确认发送；A5 自动研究最后开启。迁移不导入旧通知、旧聊天任务或待发队列。

## 实施顺序

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| A1：读取工具与来源 | 搜索、选定帖子读取、记忆检索、可见性过滤和来源记录 | 假论坛证明公开任务拿不到私信、受限分类和私人事实；引用对应真实读取内容 |
| A2：有界执行器 | 工具调用模型、任务存储、循环限制、预算、取消与恢复 | 重复工具、批量调用、预算耗尽、并发领取、取消和重启均有确定结果 |
| A3：管理员聊天台 | 会话、SSE 轨迹、证据面板、手机布局和策略表单 | 两个管理员不能互读会话；断线回放不重跑；编辑者无权使用；桌面和手机可完成研究 |
| A4：长回复与授权 | 草稿编辑、摘要绑定、目标与楼层校验、站点长度检查和统一发送门 | 指定主题只发一次；编辑后原授权失效；暂停、过期、截断、权限变化和未知发送结果均拒绝重发 |
| A5：论坛自动研究 | 普通新事件按需使用读取工具，复用模式、水位和 TTL | 默认关闭；启用后不处理启动积压；研究超时不会把过期回复送出；关闭后普通回复正常 |

A1、A2 可在模拟论坛中完成；A3 浏览器验收不发帖。真实论坛先做只读检查，A4 使用单条明确目标的回复验证，不能靠批量发帖测试。

## 新增验收条件

- 能搜索多个相关主题并给出可点击来源，来源必须对应实际读取内容。
- 能主动检索一个用户的相关事实；公开任务无法拿到私信事实或受限分类内容。
- 能在聊天台接收“介绍 SuenMeow 2.0”的任务，并依据已验证发布信息产生长草稿。
- 指定既有主题后可以发送一条完整长回复；没有目标、未授权、暂停、过期或截断时拒绝发送。
- 管理员会话互相隔离，编辑者和未登录者不能使用管理 Agent。
- 帖子内的伪管理员指令不能升级权限、调用写工具或泄露密钥与私信。
- 工具循环、总时间、步骤、并发与预算都有硬限制；取消后不会继续写入论坛。
- 超时、崩溃、刷新、SSE 重连和重启不重复发送。
