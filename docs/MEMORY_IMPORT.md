# 从个人贴建立用户记忆

状态：2026-10-05，按用户新增需求实施。个人贴导入独立于自动回复，不发帖、不 react，也不改七个人格。实现和实际验收分别记录，不能把模型候选当成已确认的事实。

## 操作流程

已验证论坛身份的用户在“记忆书架”自行操作：页面自动查找本人创建的公开主题，选择个人贴；找不到时粘贴链接或输入 ID，点击“读取预览”，先显示首帖作者、稳定用户 ID、来源与覆盖范围。设置单次 token 上限并确认这是该用户的个人贴后，再点“提取记忆”。一次模型调用产生带原句与楼层的候选；勾选后保存。编辑者只能导入本人创建的公开主题、确认并保存自己的候选，也可查看/删除自己的已保存记忆。管理员仍可为未注册用户导入，按稳定身份保管。

只接受配置论坛内的公开主题，拒绝私信、受限分类、隐藏/删除/系统帖和登录凭据。帖主由首帖真实作者 ID 确认，其他人的发言只计为已扫描，不送模型；不按标题、昵称或正文自称猜身份。其他人的评价、引用、玩笑、临时情绪不应成为用户资料。

## 预算和增量

- 默认一次最多扫描 100 个帖子 ID，每次批量读取最多 20 帖；不是全贴无限抓取。长贴分批继续，界面显示扫描量、作者原帖量、未处理量和未送入模型的量。
- 默认总预留上限 12,000 token；普通用户可在 GUI 调整为 3,000–12,000，管理员最高 30,000；输出最多 1,000 token，且不超过记忆路由自身上限。超过 6,000 字节或剩余预算的单条原帖只读取开头，明确标记截断，不能声称建立了完整用户资料。
- 模型输入按 UTF-8 字节保守预留 token，输出另设上限；先展示预留总量，再按模型返回的实际 usage 结算。单次限额与每日、同主题预算同时生效，绝不使用 topic_id=0 绕过额度。
- 普通用户每小时最多读取预览 10 次、每日最多发起 3 批模型提取和使用 20,000 token；失败/停止的提取也占批次额度，未知用量保守计账。预算锁中原子检查本人额度，不能靠取消后并发重开绕过。
- 每批最多一次记忆模型调用，无符合条件的新增内容调用为 0。失败、超时或进程重启不自动重跑，避免重复付费。
- 处理游标只在成功提取或无需提取时前进；未塞入预算的作者原帖不能因扫描水位前进而丢失。继续处理未读楼层，已完成部分不整贴重做。首版增量覆盖新帖；旧帖编辑/删除须重新核验来源，不能声称自动监听所有历史修改。
- 不逐批累积整篇摘要；候选与已保存事实按来源和正文去重。旧记忆删除后不能因重复点击同一批又自动恢复。

## 记忆与身份

每条记忆包含论坛来源、稳定用户 ID、用户名、主题/帖子 ID、原句及提取时间；模型输出必须引用实际提供的本人原帖，服务端核对原句与来源。敏感账户信息、密码、验证码、医疗或身份推断不导入；有矛盾的资料由本人或管理员选择，不自动编造统一结论。

已验证论坛身份可归属其后台账户，未注册用户先由管理员保管。首次或再次私信登录时，已有个人贴记忆按站点 + 用户 ID 归属，并同步用户名；后续身份绑定使用站点 + 用户 ID，不能按同名自动授予他人的记忆。公开来源改为私密或删除时，不再提供给公开回复或跨帖 Agent。记忆作为事实资料，原帖里的指令不能改变机器人规则。

## 验收

覆盖作者/站点核验、受限来源、引用和凭据隔离、伪造来源/原句、预算不足、分批不漏帖、重复点击、并发确认、身份归属、删除后不复活与重启不重跑。长帖测试明确比较全量输入与有界批次的 token，真实读取与模型成本另记；实际模型验收优先选管理员明确指定的公开个人贴。

## 实现入口

`memory_import.py` 提供按登录用户隔离的检测、读取、提取、取消、保存接口；worker 在暂停/只读时仍可处理用户明确创建的导入，不改变论坛水位或调用发送门。`memory_imports` 加密保存短期预览/候选，`memory_cursors` 保存站点和作者绑定游标，CLI 显式增量迁移。GUI 位于记忆书架，任务按用户隔离。使用已发布的记忆工作模块，加上不可绕过的来源协议；修改工作模块仍需发布。

## 自动发现的范围

读取本人最近 20 条创建主题记录（Discourse `user_actions` 的 `filter=4`）；该接口返回 404 时，备用查询为 `@本人用户名 in:first order:latest`，只搜索一页、取前 20 条。用户名来自已验证身份，禁止插入搜索语法。按个人贴/日记等标题优先核验最多 5 个主题，逐个验证公开性及首帖作者 ID 后才返回标题，结果按身份及论坛连接缓存两分钟；不调用模型。标题只是候选，不能认定每个主题都属于个人贴。更早的个人贴、特别标题或暂时查找失败可手动填网址，最终仍须通过同一作者校验。参见 [Discourse UserAction 定义](https://github.com/discourse/discourse/blob/main/app/models/user_action.rb)及[官方搜索说明](https://meta.discourse.org/t/searching-for-content-effectively/273328)。
