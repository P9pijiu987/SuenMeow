# 论坛私信登录与身份绑定

状态：2026-10-05。用户明确选择私信方案，不依赖论坛管理员，不再要求普通用户设置本站密码。实现已接入代码；部署、模拟与真实验收分别记录在 `ACCEPTANCE.md`。用户已亲自完成真实普通用户私信登录；只读诊断查明并修正了真实返回中的嵌套参与者字段，未用模拟记录冒充生产身份。

## 使用流程

1. 打开本站登录页，点击“获取登录验证码”。生成仅绑定当前浏览器、五分钟有效的一次性验证码。
2. 用自己的 rdfzer.com 账号，给 SuenMeow 新建一条仅双方参与的私信。可自然表达：“我要登录后台，验证码是 SM-……”。网页提供复制和打开论坛私信按钮，用户自行发送；不要发送密码。
3. 原网页等待身份确认，显示真实论坛用户名及昵称。核对后点击“确认身份并进入”。首次创建受限编辑者，再次登录使用同一个账户；昵称及头像重新同步。
4. 注册和登录的区别由服务器按论坛站点及稳定用户 ID 判断，不按昵称猜测。无需另取后台用户名或密码；内部账户标识仅用于存储。

这是通过私信证明论坛身份的无密码登录，不是共享论坛 Cookie 的 SSO。无需论坛后台配合，正常登录不调用 AI，机器人也不需要回复私信，因此不会提前触发首次论坛发送。

## 已核验的站点能力

只读检查确认当前论坛提供稳定用户 ID、用户名、昵称和 avatar_template，Reactions 已开启。User API HEAD 返回版本 4，但机器人账号的 session_info 授权预览返回 no_trust_level，本站回调预览返回 generic_error；没有签发密钥。这不能代表所有普通用户的权限相同。

DiscourseConnect 需要论坛管理员配置；User API 也受组权限及回调白名单限制。用户现阶段无法取得管理员配合，因此采用私信验证，不收集论坛密码。官方机制参见 [DiscourseConnect](https://meta.discourse.org/t/use-discourse-as-an-identity-provider-sso-discourseconnect/32974)与 [User API](https://meta.discourse.org/t/user-api-keys-specification/48536)。

## 服务端边界

- 验证码具有 128 位随机性，仅存摘要；浏览器凭据另行生成，保存在 HttpOnly/Secure/SameSite Cookie。取得验证码不能从另一浏览器查询或消费原请求。过期、再次生成、关闭登录或论坛连接变化使旧请求失效。
- 仅接受申请创建之后的新原帖，必须为真实二人私信、非机器人作者、非群组、非引用、非隐藏/删除/系统帖；论坛返回的作者 ID 必须与参与者及用户资料 ID 一致。正文自称的身份无效。
- 确认时事务内消费请求、建立唯一身份并创建会话。同一验证码最多成功一次；并发消费和同一身份多次首次登录不会创建多个账号。既有手动绑定的旧账户不能通过同名自动被接管，需管理员核验迁移。
- 角色固定 editor，不能自选权限或发布。禁用账户不得重新注册绕过封禁。已有 TOTP 的绑定账户仍需验证码，并限制确认尝试；管理员原有密码登录保留。
- 头像仅通过本站代理从同一论坛来源读取，限制大小及图片类型，不跟随跳转，不接受任意外部 URL。读取失败显示昵称首字；昵称和头像不参与权限判断。
- 普通用户使用私信重新验证身份，登录界面不提供密码设置。兼容密码账户仍可管理原有密码及 TOTP；首次论坛账户的独立 TOTP 设置还需基于身份重新验证的专门流程，不能显示无法使用的旧密码表单。

## 数据、接口与 GUI

新增 `forum_logins` 和 `forum_identities` 两张表，`identity_schema=1` 标记增量迁移；原 schema 2、账户及发布快照保留。身份唯一约束为站点 + 用户 ID，每个身份关联一个后台账户。

- `GET /api/auth/forum`：可用入口、机器人用户名和论坛地址。
- `POST /api/auth/forum/start`：同源发起请求；每地址每小时 10 次、全站 120 次，最多 100 个未过期待验证请求。
- `GET /api/auth/forum/status/{id}`：只在原浏览器读取状态；不消费凭据。短暂网络错误保留请求继续轮询，支持“我已发送，立即检查”。
- `POST /api/auth/forum/finish/{id}`：同源确认并原子消费，必要时验证 TOTP；建立原有受保护会话。
- `PUT /api/auth/forum`：管理员控制登录及首次注册；关闭新注册仍允许既有身份登录。
- `GET /api/auth/avatar/{account_id}`：本人/管理员读取受限头像代理。

worker 在暂停或只读模式也能核验待登录请求，独立于模型连接。仅有待验证请求时，每五秒批量读取新通知及有限候选私信；无请求时关闭额外论坛会话。通知候选有上限，超出时用户可重新申请；不能谎称已经扫描全部历史私信。

登录页默认显示论坛验证；管理员/旧账户入口保留。后台显示论坛昵称和头像，账户页显示真实绑定，禁止手工改绑已验证身份。生产切换到私信后关闭无身份的网页自由注册，管理员仍可创建或管理旧账户；避免在私信入口尚不可用时关闭所有入口。

## 验证消息隔离与发送安全

注册/登录验证码或显式账号密码消息在普通聊天、摘要、记忆和研究前隔离，不能发给模型或成为研究证据。审计只保存请求 ID、论坛 ID 和状态，不保存明文验证码或私信正文。验证码不在 URL 中传给本站，状态接口不缓存。

SuenMeow 不代用户创建私信、不回复验证码、不 react 登录消息，不需要发送权限。只处理有效的用户主动登录请求；重启最多恢复尚未过期的验证，不会补发积压。实际私信由用户亲自发出，登录检查本身只有论坛读取。

## 验收要求

模拟/数据库测试覆盖真实作者、公开帖、群聊、引用、旧消息、假资料、隐藏帖、错误主题、浏览器绑定、同源、限速、过期/替换、旧绑定、防封禁绕过、一次消费、并发消费及 TOTP。暂停核验不依赖模型或产生发送；敏感正文不进入模型上下文，头像不能用于访问外部或内部来源。

浏览器验证桌面/手机的请求、等待、核对、确认、昵称/头像及受限工作区。真实公开入口先验证请求与安全边界，再由普通用户发送一条新私信完成真实绑定；模拟作者不得写入生产验收。首帖发布还须完成 `INTERACTION.md` 的回复改革与 reaction 验收，所有七个 persona 保持不变。
