# 记忆如何参与回复

## 普通回复：相关事实检索

记忆是独立、加密的事实记录，带作者、来源和公开/私信范围，不会修改人格或系统工作提示词。普通回复使用 JSON 资料中的 `memory` 字段，而不是把用户整个书架追加到 system prompt。

1. 扫描记忆目录，按站点、当前主题、参与者用户名及稳定论坛 ID 筛选；不再截断为全站最近 500 条。私信事实只能留在同一站点的原私信。
2. 用最近有效用户发言进行本地关键词排序，相关事实优先，最多补充两条背景事实；不调用 embedding 或模型 API。
3. 核验来源当前可见性；个人贴事实再次验证作者、非空原句及非引用状态。删除、改为私密或无法核验的来源不使用，普通检索最多检查六个来源主题。
4. 最终最多六条，每条最多 300 UTF-8 字节，附作者、来源帖子和记录 ID。服务端明确提示这是选段，不能据此声称用户“只有两条记忆”。

Agent 的 `memory_lookup` 可按用户名、主题或关键词检索最多六条有来源事实。结果带 `complete=false`、`total=null`，不能拿检索命中数量当书架总数。

## Agent：读取全部记忆

`memory_read_all` 是独立的只读工具，后台「与猫交谈 → 研究策略」可启用或撤销。新安装默认包含此工具；已有安装需要显式启用，不自动扩大旧管理员的工具授权。

例如交代：“读取 P9pijiu 的全部记忆，整理主要经历和偏好；如果没有读完，请告诉我。”

- 首次参数是 `username`，可带稳定 `user_id`；后续使用返回的 `next_cursor`。默认每页检查 50 条目录记录，最多 100 条，单页事实列表限制 40,000 UTF-8 字节，另有少量进度字段。分页是内部工具调用，用户不用手动一批一批点击。
- 首次冻结记录 ID/版本目录，按保存时间排序；不做关键词过滤，不遗漏早期记录。事实正文完整返回，最多 2,000 字符。新增、编辑或删除的记录不会偷偷混入旧目录。
- 先核验来源主题可见性，再验证准确帖子 ID、作者身份、个人贴原句及验证消息隔离；同一任务缓存已读来源，每次论坛批量读取最多 20 个帖子。来源不合格的内容、标题和数量不返回。
- `read_count` 是累计已提供的可用事实数。只有 `complete=true` 才提供核实后的 `total` 和 `remaining=0`；否则总数与剩余数量为 `null`，并返回续读位置、未完成提示和可能的限制原因。
- 仍受任务步骤、不同主题数、总时间和 token 预算限制。预算或时间耗尽时保留已读进度；达到限制必须说明“已读多少，尚未读完”，不能把部分记忆当作全部。总数是此次目录中核验通过的可用事实数，不包括其他私信、受限来源或其他站点。
- 续读位置只属于本任务与该用户，不能换用户、跨任务或重启后继续；新任务重新核验。引用的记录绑定版本，发送前删除或修改记忆会使旧草稿失效。

用户在被选中的论坛回复中明确要求“读取我的全部记忆”时，可在关闭非请求式自动研究的情况下触发受限记忆研究；该例外只允许记忆工具与已指定对话读取，不增加发送权。其他闲聊仍用相关检索。无法开始或完成读取时明确说明限制。

## 未实现的方向

当前词法检索仍可能漏检近义词、繁简表达与隐含话题。分层记忆、缓存向量、期限及矛盾合并尚未实现。完整读取不保证模型总结绝对准确；书架仍可查看来源与删除记录。不要为每条论坛消息重新总结整本书架。
