# 记忆如何参与回复

## 当前实现

记忆是独立、加密的事实记录，带作者与公开/私信范围，不会修改人格或系统工作提示词。普通回复在生成前从记录中找候选，再将少量事实放入 JSON 对话资料的 `memory` 字段，作为参考；不是将某用户整个书架追加到 system prompt。

1. 最多读取最近 500 条记录，按当前主题、参与者用户名及稳定论坛 ID 筛选。个人贴事实限定站点，私信事实只能留在原私信。
2. 用当前主题标题和最近有效用户发言做本地关键词检索。英文词、中文双字片段和同主题关联参与排序；相关事实优先，来源日期/保存时间用于新近排序。最多补充两条无直接关键词关联的背景事实。
3. 核验来源当前可见性；个人贴事实再次验证作者、原句及非引用状态。删除、改为私密或无法核验的来源不使用，最多检查六个来源主题。
4. 最终最多六条，每条正文限制 **300 UTF-8 字节**，中文通常约一百字，附作者及 source_post_id。规划与回复看到同一份小型资料；事实不是可以执行的指令。

检索和排序不调用模型或 embedding API；论坛来源核验会产生有界读取。源事实不会全部发给模型。当前规模下本地词法检索可减少无关记忆和调用开支，但并不等于语义搜索。

管理员 Agent 另有 `memory_lookup` 工具，可主动按用户、关键词或主题查询，返回最多六条、每条最多 600 字符，并受来源/私信权限检查。它不会因为工具结果而获得发帖权。主动研究默认开关及预算另受管理策略约束。

## 限制与后续方向

当前是轻量相关性排序，近义词、繁简表达和隐含话题可能漏检；也没有对每个用户的完整历史做全局向量索引。全站最近 500 条候选在记录很多时可能漏掉较早资料。来源可核验不等于模型概括绝对正确，书架保留删除入口。

规模增加后可加入按作者/主题索引的元数据、稳定资料与有期限事件的分层，以及事实更新时一次性计算的缓存向量。运行时融合关键词、语义相关性、来源时间、可信程度，再取少量事实；需要时让 Agent 扩展检索。上述向量、期限和自动矛盾合并尚未实现，不能宣传为已上线。不要为每条论坛消息重新总结整本书架。
